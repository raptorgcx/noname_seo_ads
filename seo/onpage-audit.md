# Он-пейдж аудит — nonamelounge.ro + каталог

Свежесть: 2026-07-13. Проверено по коду в репах noname_site (site/*.html,
assets/js/analytics.js) и noname_parser (exporters/pubsite.py). Не проверялись: страницы
QR-меню и privacy (утилитарные, SEO-веса не несут; гляну хвостом), скорость по
Lighthouse (статик на VPS — априори быстрый, замерю при бейзлайне).

## Вердикт коротко

Сайт в **хорошей** он-пейдж форме — переписывать тексты не нужно. Есть 3 точечные
технические правки (одна критична для будущей рекламы) и контент-разрыв в каталоге.

## Главные страницы (4 языка) — что уже правильно

- Title с ключом+гео на каждом языке: «NO NAME Lounge — Narghilea, Sushi & Cocktails
  în Băneasa, București» (RO), аналоги RU/EN/UA. Менять не надо.
- Meta description с CTA и телефоном; canonical на каждой; hreflang ro/ru/en/uk
  перекрёстно; og-теги живые.
- Плотность ключей здоровая без спама: RO-главная — narghile* ×11, hookah ×5, Băneasa ×7.
- JSON-LD BarOrPub с NAP, часами, sameAs (IG/FB).

## Правки (по приоритету)

### P0 — consent-баннер блокирует будущий Google Ads ⚠️
`analytics.js`: после «Принять» GA4 грузится с `ad_storage/ad_user_data/
ad_personalization: denied` **навсегда** — grant-пути нет (строки 41–44). Аналитике не
мешает, но конверсии Ads не свяжутся с кликами (gclid не сохранится) — любая кампания
будет выглядеть провальной при живых бронях.
**Фикс** (handoff noname_site): «Принять» = granted и для ad_*; «Отклонить» — как есть.
Одна правка + бамп `?v=4`. Сделать ДО первой кампании (пре-флайт Т1).

### P1 — hreflang x-default отсутствует на главных
Каталог шлёт `x-default` → RO, главные — нет. Для Google при 4 языках это
разрешатель «кому показать неязыковой запрос».
**Фикс**: `<link rel="alternate" href="https://nonamelounge.ro/" hreflang="x-default">`
в 4 главных (+ проверить шаблон gen-menu-qr.ps1).

### P1 — JSON-LD дозаполнить
Сейчас нет: `geo` (координаты — для локалки полезно), `priceRange` («150–300 RON»
по факту меню), `hasMenu` → https://nonamelounge.ro/meniu-qr/, `description`.
⚠️ `postalCode: 077190` — это индекс коммуны Ilfov; Bd. Ficusului 2A (Sector 1) должен
быть 013975-ish — **проверить и поправить** (NAP-консистентность с будущим GBP важна).
Красная линия остаётся: никакого aggregateRating.

### P2 — сезонный блок «terasa» (тест Т6)
Терраса существует (зона в виджете брони), но словом «terasă cu narghilea» страница
почти не говорит. Дешёвый сезонный хвост: упоминание в H2/абзаце секции Atmosfera или
прайса, на 4 языках. Без отдельной страницы.

### P3 — H2 без ключей
Все H2 главной — брендовые («Prețuri fără steluțe»). Это сознательный стиль, конверсию
не трогаем; если Т6 делаем — одна H2 с «narghilea/terasa» закроет и это.

## Каталог HookahRadar — что уже правильно

Шаблон здоровый: точное имя заведения в title/H1 («{name} — {kind} {sector} |
HookahRadar»), x-default есть, JSON-LD, sitemap, hreflang, версионирование ассетов.
Рейтинги текстом с ссылкой на источник — правильно (без разметки).

### Разрыв один — покрытие: 28 заведений из 48 сидячих
Топ непокрытого брендового спроса: Zaitoone (5952 отзыва), HiroBay (2015), Mezeya
(1347), Bemolle (1273), Habibi (1247)… — полный список с приоритетами в
`semantics.md`, кластер D. План: +20 заведений (60 страниц), партиями по 5–10,
ручной копирайт в `noname_parser/content/copy.yaml` (политика сохраняется).

### Идея на тест (Т5): секторные хабы
Сейчас хаб один (город). Страницы «Narghilea Sector 1..6» с фильтром заведений сектора
закрыли бы кластер C. Данные есть (sector у каждого заведения), шаблон хаба есть —
доработка pubsite.py. Делаем после партии карточек: карточки — проверенный спрос,
хабы — гипотеза.

## Чего сознательно НЕ делаем

- Не раздуваем тексты главной ключами — конверсионный лендинг важнее плотности.
- Не добавляем aggregateRating и не цитируем текст Google-отзывов (ручная санкция /
  лицензия — красные линии проекта).
- Не строим отдельный блог под инфозапросы «как делать кальян» — интент не броневой,
  каталог даёт больше на той же энергии.
